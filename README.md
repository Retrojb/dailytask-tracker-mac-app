# Retro Daily Tracker Widget

A macOS widget app for logging daily work activities. Sends 3PM EST weekday reminders, supports ad-hoc notes throughout the day, syncs entries to Google Sheets or Microsoft Excel, and shows random animal pictures on demand.

## Architecture

The project is split into two targets that share data via an App Groups container:

- **RetroDailyTracker** — Companion App (SwiftUI host). Manages data entry, notification scheduling, spreadsheet sync, and settings.
- **DailyTrackerWidget** — Widget Extension (WidgetKit). Displays today's summary, provides quick-action buttons for adding notes and fetching animal pictures.

Both targets share models, protocols, and services through the `Shared/` directory. Data flows between them using a shared SwiftData store inside the App Group container (`group.com.retro.dailytracker`).

## Setup

### Prerequisites

- macOS 14.0+ (Sonoma)
- Xcode 15.0+
- [XcodeGen](https://github.com/yonaskolb/XcodeGen) — install via `brew install xcodegen`
- An Apple Developer account with the App Group `group.com.retro.dailytracker` provisioned

### App Group Configuration

The App Group `group.com.retro.dailytracker` must be registered in your Apple Developer account and enabled in both the Companion App and Widget Extension provisioning profiles. Without this, data sharing between the app and widget will not function.

### OAuth Credentials

Spreadsheet sync requires registered OAuth client IDs:

- **Google Sheets** — Register an OAuth 2.0 client in the Google Cloud Console
- **Microsoft Excel** — Register an app in the Azure Portal (Microsoft identity platform)

Replace the placeholder client IDs in `RetroDailyTracker/Sources/Services/SpreadsheetService.swift` with your own credentials.

## How to Build

### Regenerate the Xcode project (if needed)

```bash
xcodegen generate
```

Run this after modifying `project.yml` or when cloning for the first time without the `.xcodeproj` checked in.

### Build with Xcode

```bash
open RetroDailyTracker.xcodeproj
```

Select the **RetroDailyTracker** scheme and build (Cmd+B). The scheme builds both the Companion App and the Widget Extension.

### Build from the command line

```bash
xcodebuild build -scheme RetroDailyTracker -destination 'platform=macOS'
```

### Run tests

```bash
xcodebuild test -scheme RetroDailyTracker -destination 'platform=macOS'
```

## How to Run

1. Build the project using Xcode or `xcodebuild` (see above).
2. Run the **RetroDailyTracker** scheme from Xcode (Cmd+R), or locate the built `.app` in the derived data folder.
3. Grant notification permissions when prompted — required for daily reminders.
4. Add the widget: right-click the Desktop or open Notification Center, click "Edit Widgets", and add **Daily Work Tracker**.

## Quirks

- **App Group provisioning** — The App Group container must be properly provisioned in your Apple Developer account. The app and widget won't share data without it.
- **OAuth client IDs** — Placeholder IDs ship in the repo. You need to register your own and update `SpreadsheetService.swift`.
- **Widget refresh rate** — WidgetKit enforces a minimum ~15-minute timeline reload interval. Widget content won't update instantly after logging an entry.
- **Notification permissions** — If the user denies notification access, the app displays a banner with a link to System Settings. Reminders won't fire until permission is granted.
- **XcodeGen required** — The `.xcodeproj` is generated from `project.yml`. Run `xcodegen generate` if the project file is missing or stale.
- **macOS 14.0+ required** — Interactive widget buttons (App Intents) require Sonoma or later. The app will not build for earlier macOS versions.
